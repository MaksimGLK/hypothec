# Ипотечный планировщик

Веб-сервис (позже — приложения для iPhone и Android), который помогает семье спланировать покупку жилья в ипотеку: этапы сделки, расходы по датам, распределение доходов по счетам, подушку безопасности и досрочное погашение.

Все расчёты носят информационный характер и строятся только на данных, которые ввёл пользователь.

Архитектура и модель данных: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Требования

- Node.js 22+
- pnpm 10 (`npm i -g pnpm@10` или `corepack enable`)
- Docker (Postgres и почта для разработки; интеграционные тесты API поднимают Postgres сами через Testcontainers)

## Запуск для разработки

```bash
pnpm install
cp .env.example .env
pnpm db:up          # Postgres на :5433 и Mailpit (письма — http://localhost:8025)
pnpm dev:api        # API на http://localhost:3000, документация — http://localhost:3000/api/v1/docs
pnpm dev:worker     # фоновые напоминания (в отдельном терминале)
pnpm dev:web        # веб на http://localhost:5180 (запросы /api проксируются на API)
```

API при старте сам применяет миграции и загружает уроки, словарь и правила рекомендаций из `packages/content`.

Всё в Docker, как на сервере:

```bash
cp .env.example .env   # поменяйте секреты
docker compose --profile app up -d --build   # веб — http://localhost:8080, API — там же, /api/v1
```

Порты слушают только `127.0.0.1`. С другой машины удобно открыть через SSH-туннель: `ssh -L 8080:localhost:8080 сервер`.

## Тесты

```bash
pnpm test        # все тесты (ядро, контракт, API на настоящем Postgres)
pnpm typecheck   # проверка типов
```

Сквозной тест интерфейса (Playwright в Docker; нужны запущенные API, веб и Mailpit): проходит путь семьи от регистрации и подтверждения почты до плана, досрочки и урока — на телефоне и компьютере, снимает скриншоты в `apps/web/e2e/.screens`.

```bash
pnpm e2e                                   # против pnpm dev:web (http://127.0.0.1:5180)
WEB_URL=http://127.0.0.1:8080 pnpm e2e     # против сборки в Docker
```

Если Docker недоступен, интеграционным тестам можно дать готовую базу: `TEST_DATABASE_URL=postgres://… pnpm --filter @hypothec/api test`.

Только ядро, в режиме наблюдения:

```bash
pnpm --filter @hypothec/core exec vitest
```

## Структура

```

  api-contract/   Zod-схемы запросов и ответов — общие для бэкенда, веба и мобилки
```

### Что умеет ядро (`packages/core`)

| Модуль | Что делает |
|---|---|
| `money` | Копейки как целые числа, `decimal.js` для промежуточных расчётов, банковское округление, формат «1 234 567 ₽» |
| `loan` | Аннуитет и дифференцированный платёж; проценты «ставка/12» или по фактическим дням; смена ставки с даты; досрочка разовая и ежемесячная в трёх режимах (срок / платёж / «уменьшить платёж, но платить прежнюю сумму»); правила банка; сравнение до 4 сценариев; «1 млн сейчас vs через 5 лет»; импорт CSV-графика банка и сверка |
| `income` | Доходы с периодичностью и надёжностью, привязка к дате ключей, быстрый ввод одной строкой («Премия 110 000 каждый месяц 15-го») |
| `expenses` | Расходы план/факт, ежегодная страховка от остатка долга до конца кредита, «после ключей» с приоритетами, справочник типовых расходов |
| `allocation` | Календарь распределения: с какого поступления сколько и на какой счёт перевести, чтобы к дате платежа деньги были на месте; порядок целей; резерв на ежегодные платежи; дефициты |
| `cushion` | Цель подушки, прогноз даты, стресс-тест «что если пропадёт доход» |
| `tax` | Вычет с покупки (до 2 млн ₽ базы) и с процентов (до 3 млн ₽) на каждого супруга с учётом уплаченного НДФЛ; «направить вычеты в досрочку» |
| `stages` | Шаблоны этапов под новостройку, вторичку, дом; мастер, который собирает черновик плана |
| `recommendations` | Движок: факты плана → условия (JSON-Logic, данные) → эффект в рублях (калькуляторы в коде) → текст; сортировка, скрытие и откладывание, объяснение |
| `calendar` | Единая лента событий: платежи, поступления, переводы, этапы, страховка, досрочка, заявление, декларация |
| `projection` | `buildPlan(input)` — единая точка пересчёта всего плана (≈20–60 мс на горизонте 10–30 лет) |

### Бэкенд (`apps/api`)

| Что | Как |
|---|---|
| Вход | Email + пароль (argon2id), проверка на слабые пароли, блокировка после 10 неудачных попыток на 15 минут. Коды на почту — для подтверждения адреса, сброса пароля и удаления аккаунта |
| Токены | Access JWT на 15 минут. Refresh-токены на 60 дней с ротацией: повторное использование старого токена отзывает всю цепочку. Веб получает refresh в httpOnly-cookie, мобильные клиенты — в теле ответа |
| Будущие способы входа | Таблица `auth_identities` (провайдер + идентификатор): VK ID, Яндекс ID, Сбер ID, телефон добавляются без изменения схемы |
| Семья | Владелец и участники, приглашение по email на 7 дней, передача прав. Чужая семья для API не существует (404) |
| Совместная правка | У каждой записи версия; правка со старой версией получает 409 и не затирает изменения супруга |
| Пересчёт | Любое изменение повышает ревизию семьи; план пересчитывается по запросу и кэшируется по ревизии и дате |
| Напоминания | Воркер на pg-boss: после правок плана (с задержкой в минуту) и раз в сутки пересобирает напоминания, каждые 5 минут отправляет наступившие — одним письмом на человека. Настройки по типам событий и «за сколько дней». Модель общая для email и будущих push |
| 152-ФЗ | Согласие на обработку ПДн с версией документа и IP, выгрузка всех своих данных (`GET /me/export`), полное удаление аккаунта по паролю и коду из письма. Никаких внешних сервисов, кроме своего SMTP |
| Документация | OpenAPI: `/api/v1/docs`; файл для мобильного клиента — `pnpm --filter @hypothec/api openapi > openapi.json` |

### Бюджет на жизнь и режимы

- **Бюджет:** категории расходов (коммуналка, продукты, транспорт, кружки, кафе…) с планом на месяц и фактом. Траты вносятся покупками одной строкой — «пятёрочка 3 450» сама ляжет в «Продукты». Видно, сколько осталось до конца месяца и сколько можно тратить в день; по истории подсказывает средний факт и предлагает поправить план. Обязательные категории входят в подушку и стресс-тест, необязательные (кафе, развлечения) — нет. Мастер сразу спрашивает основные расходы. Советы: «укажите расходы на жизнь», «прошлый месяц — сверх плана».
- **Простой и продвинутый режим** для всего приложения, хранится в профиле (общий для веба и телефона). Простой: главная, бюджет, доходы, кредит, досрочка одной суммой, сделка, подушка, советы, уроки. Продвинутый добавляет счета и переводы, расходы сделки, сценарии и сравнение досрочек, календарь, налоговый вычет, смену ставки, правила банка и сверку с графиком банка.

### Веб-клиент (`apps/web`)

- **Разделы:** вход и регистрация с согласием на ПДн, мастер (6 шагов), главная, этапы сделки, доходы (быстрый ввод одной строкой и шаблоны), расходы (план/факт, «после ключей», ежемесячные траты, справочник), счета и календарь переводов с порядком целей, кредит (параметры, смена ставки, правила банка, графики, импорт CSV), досрочка, подушка и стресс-тест, календарь (с выгрузкой в .ics), советы, налоговый вычет, уроки и словарь, семья, настройки, мои данные.
- **Досрочка считается прямо в браузере** тем же ядром `@hypothec/core`, что и на сервере: ввели сумму — сразу видно экономию в трёх режимах, без запроса к серверу. Так же будет в мобильном приложении.
- **Только через публичное API:** веб не делает ничего, чего не сможет мобильный клиент. После любой правки перечитываются данные семьи, пересчёт делает сервер.
- **Термины** подчёркнуты пунктиром и объясняются по нажатию (словарь с сервера), **уроки** появляются на тех экранах, к которым относятся.
- **Телефон в первую очередь:** нижняя панель из пяти разделов, окна выезжают снизу; на компьютере — боковое меню. Светлая и тёмная тема (или как в системе).
- **Безопасность:** access-токен только в памяти вкладки, refresh — в httpOnly-cookie. В продакшене nginx отдаёт веб и проксирует `/api` на том же домене со строгим CSP. Внешних шрифтов, скриптов и аналитики нет.

### Мобильное приложение (`apps/mobile`)

Заготовка на Expo SDK 57 (React Native 0.86, expo-router):

- вход по почте и паролю; refresh-токен приходит в теле ответа и хранится в SecureStore (Keychain / Keystore), access-токен — только в памяти;
- главный экран из того же `GET /dashboard`, что и у веба;
- траты одной строкой на ходу и бюджет месяца по категориям;
- калькулятор досрочки в трёх режимах — считается на телефоне тем же `@hypothec/core`, без сети;
- светлая и тёмная тема с цветами веба.

Metro собирает общие пакеты прямо из TypeScript-исходников монорепозитория ([metro.config.js](apps/mobile/metro.config.js)). Проверка, что бандл собирается: `pnpm --filter @hypothec/mobile bundle:check`.

Запуск: `pnpm dev:mobile`, затем Expo Go или эмулятор. Адрес API — `extra.apiUrl` в [app.json](apps/mobile/app.json): `10.0.2.2` для эмулятора Android, `localhost` для симулятора iOS, IP компьютера в локальной сети для телефона.

Дальше: остальные разделы, push-напоминания (модель уведомлений и `POST /me/push-devices` уже есть), регистрация в приложении, вход через VK ID / Яндекс ID / Сбер ID.

### Уроки и словарь

[packages/content/lessons](packages/content/lessons) — 7 коротких уроков в Markdown: аннуитет, подушка, досрочка, налоговый вычет, страхование, эскроу и аккредитив, типичные ошибки и мошенничество. У каждого есть источники, дата проверки, блок «В вашем случае» с подстановкой цифр семьи и вопросы для самопроверки. [glossary.json](packages/content/glossary.json) — словарь терминов для всплывающих подсказок. Тексты обновляются без выпуска приложения: при старте API они загружаются в базу (или вручную: `pnpm --filter @hypothec/api content:sync`).

### Правила рекомендаций

Стартовый набор лежит в [packages/content/rules/starter.json](packages/content/rules/starter.json). Правило — это данные: условие на фактах ядра, имя калькулятора эффекта, текст с подстановками, действия, источники и дата проверки. Новое правило на существующих фактах не требует выпуска приложения. Список доступных фактов — `FACT_DESCRIPTIONS` в [facts.ts](packages/core/src/recommendations/facts.ts); проверка правила перед публикацией — `validateRule()`.

## Принятые упрощения в расчётах

- Досрочка между датами платежей целиком идёт в основной долг; проценты за дни до неё остаются в ближайшем обязательном платеже.
- Новая ставка меняет размер платежа с ближайшей даты платежа; проценты по новой ставке считаются с даты смены.
- В режиме «ставка/12» первый неполный период считается как полный месяц.
- Стоимость страховок по умолчанию — ориентир в % от остатка долга; пользователь вводит свою сумму.
- Ставки льготных программ в мастере — только ориентир для черновика (`PROGRAM_DEFAULTS`), пользователь вводит ставку из своего одобрения.
